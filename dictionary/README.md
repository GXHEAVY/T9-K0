# Dictionary reference

`words_en.tsv` holds the production word list (`word<TAB>zipf`). It is generated by
`fetch_sources.py` from pinned inputs and committed as a derived data file.
`build_t9_dictionary.py` (`make dict`) packs it into `keymap/t9_dictionary_data.h`; see the
[packed dictionary format](#packed-dictionary-format) below. Licences and required attribution are in [LICENSES.md](../LICENSES.md):
the data is CC BY-SA 4.0; combined firmware distribution uses the GPLv3
compatibility route, subject to the dependency review recorded there.

## Reproduce

Use Python 3.12 or newer. The source-fetching tools are separate from the
standard-library-only packer; ordinary firmware builds use the included data.

```sh
make fetch-sources
# equivalent to:
python3 -m venv .venv-dict
.venv-dict/bin/pip install -r dictionary/requirements.txt
.venv-dict/bin/python dictionary/fetch_sources.py --output dictionary/words_en.tsv
```

The script:

1. downloads the wordfreq wheel and the SCOWL tarball into `dictionary/sources/`, which
   is gitignored;
2. checks both sha256 values against `sources.lock` and exits non-zero on a mismatch;
3. checks that the installed `wordfreq/data/large_en.msgpack.gz` is byte-identical to the
   copy in the pinned wheel;
4. extracts only the SCOWL `final/` lists, `Copyright`, `README` and `VERSION`, and the
   wheel's `LICENSE.txt` and `METADATA`. These are read as data and nothing from them is
   executed.

Output is deterministic for the same pins. The committed `words_en.tsv` sha256 is
recorded in the local `report.md` generated by `make dict`. Generated reports
are gitignored; they are diagnostics rather than build inputs.

`--write-lock` updates the pins: it takes the wheel hash from PyPI's JSON API,
measures the SCOWL hash, records the current date and rewrites `sources.lock`.
Use it for intentional source updates and review the diff.

## Filters

- wordfreq tokens are kept when they match `^[a-z]{1,24}$`. Apostrophe forms (`don't`)
  are dropped because the engine handles apostrophes separately. Accented and digit
  tokens are also dropped.
- Zipf is `log10(frequency) + 9` rounded to two decimals, and must be at least
  `--min-zipf` (default 2.0).
- The token must also be in SCOWL en_US: the `english` and `american` spelling categories,
  sub-categories `words`, `proper-names` and `upper`, sizes up to `--scowl-size` (default
  70), lowercased, and only entries that are pure a-z. Abbreviations, contractions,
  variants, other regional spellings and the special lists are excluded.
- Single-letter tokens are kept only for `a` and `i` (`--single-letters`, default `ai`);
  the other 24 letters have zipf 4.5-5.9 in wordfreq and would otherwise occupy the first
  candidate of every one-digit sequence.
- Contraction parts: both sides of every apostrophe token with zipf >= min-zipf are added
  as words with the token's zipf (`don't` -> `don`, `t`; `i've` -> `i`, `ve`), bypassing
  the SCOWL filter and the single-letter rule, so `don` `'` `t` predicts "don't". 470 new
  words come from this step (`s t m ve didn doesn ll isn d wasn ...`); `--no-contractions`
  disables it. The report lists them.

The engine also predicts common contractions through a separate 417-byte table in
`keymap/t9_contractions.c`: one `1` between the base and suffix digits stands for an
apostrophe. Dictionary fragments also support manual punctuation entry; the
table avoids materializing all
base/suffix combinations or arbitrary possessives in the word list.
The resulting source list is sorted by Zipf frequency descending, then word ascending.

## Changing the word budget

Pass `--min-zipf` to change the size of the list. `--scowl-size` and
`--no-scowl-filter` change how strict the allow-list is. Measured with the current pins:

| Options | Words kept |
|---|---|
| `--min-zipf 1.5` | 77,092 |
| **`--min-zipf 2.0` (default, committed)** | **59,757** (825,837 bytes; 59,311 plain words + 470 contraction parts, minus 24 single letters) |
| `--min-zipf 2.5` | 41,675 |
| `--min-zipf 3.0` | 25,802 |
| `--scowl-size 80` | 65,000 (adds UKACD, which has its own verbatim-notice requirement; see LICENSES.md) |
| `--no-scowl-filter` | 89,656 |

The flash budget is enforced later, by `make dict` with `--max-bytes`, which also keeps
at most `--max-exact` (10, `T9_MAX_EXACT`) words per digit sequence, dropping the rarest
first; with the current list nothing survives into the budget that the cap would drop.
This list is the input to that step and does not have to fit in flash itself. Pass
`--output` and `--report` to experiment without overwriting the committed files.

## Generated reports

`make fetch-sources` writes `dictionary/report_sources.md` with filter counts,
removed tokens and added contraction fragments. `make dict` writes
`dictionary/report.md` with hashes, packed size, word histograms and fixture
coverage. Both reports are local, generated files; neither is needed to build.

The en_US filter excludes many British/Commonwealth spellings and informal words.
Use multitap for missing words, or adjust the source filters and inspect the
reports before regenerating the packed dictionary. Run `make test` afterwards.

## Packed dictionary format

Read-only data generated by `dictionary/build_t9_dictionary.py` and decoded by
`keymap/t9_dict_packed.c`. Format changes require matching generator and decoder
updates, size measurements and lookup-equivalence checks.

### Ordering

Entries are sorted by digit sequence (lexicographic over digit values, a shorter
sequence before any extension of it), then by score descending, then by word
ascending. Consequences used by the decoder:

- all words with digit sequence `D` are contiguous and in rank order;
- all words whose digit sequence starts with `D` form one contiguous range that
  begins with the exact matches of `D`.

The same ordering rule defines candidate rank in `t9_dictionary.h`, so a plain
`{word, score}` table (`t9_dict_simple.c`) and the packed decoder must return
identical windows for identical word lists.

### Bitstream

MSB-first bit packing into `uint8_t t9_dict_bits[]`. One entry:

| field | bits | meaning |
|---|---|---|
| `shared` | 5 | leading digits shared with the previous entry of the same block; 0 for the first entry of a block |
| `len` | 5 | word length in letters, 1..24 (`T9_MAX_WORD_LEN`) |
| `suffix digits` | 3 x (`len` - `shared`) | digit value minus 2, in order |
| `letters` | 2 x `len` | index of each letter within its digit group (`t9_digit_letters`), all letters of the word |
| `score` | 6 | quantized zipf: `clamp(round(zipf * 8), 0, 63)` |

Entries are grouped into blocks of `T9_DICT_BLOCK_SIZE` (64 by default; the
generator's `--block-size` changes it, which the host fixture uses to span many
blocks) consecutive entries; the last block may be shorter. There is no
per-entry terminator: the block's entry count is known from the word count.
The bitstream is zero-padded to a whole byte.

### Index

- `uint32_t t9_dict_block_offsets[block_count + 1]`: bit offset of each block's
  first entry; the final element is the total bit length.
- `uint8_t t9_dict_block_max_score[block_count]`: highest score in the block,
  used to skip blocks that cannot improve the completion table.
- `#define T9_DICT_WORD_COUNT`, `T9_DICT_BLOCK_COUNT`, `T9_DICT_BLOCK_SIZE`,
  `T9_DICT_DATA_BYTES` (bitstream + both index arrays).

`--max-bytes` applies to `T9_DICT_DATA_BYTES`, i.e. everything the data header
contributes to flash, not to the bitstream alone:
`ceil(bits / 8) + 4 * (block_count + 1) + block_count`. Words are dropped in
order of score ascending, ties by word descending, until it fits (binary search
over the kept count, then stepping down, since restart blocks make size not
strictly monotone).

### Lookup algorithm (decoder)

1. Binary search the block index for the last block whose first sequence is
   `< D` (strictly); start there (block 0 when none). With `<=`, exact matches
   of `D` at the end of the previous block would be missed when a block starts
   with `D`.
2. Decode entries in order, maintaining the current sequence from `shared` and
   the suffix digits. Stop at the first sequence that is `> D` and does not
   start with `D`.
3. Sequences equal to `D` are exact matches in rank order; the first
   `T9_MAX_EXACT` are kept (the generator's `--max-exact` already drops the
   rest, so the production data never has more). Longer sequences are
   completions: each whole word goes into a top-`T9_MAX_COMPLETIONS` table
   ordered by (score desc, length asc, text asc), its letters decoded when it
   is offered. An entry whose score is below the lowest score of a full table
   is not decoded. Exact matches are all seen before any completion.
4. At a block boundary inside the range, once every exact match has been seen
   (some entry of the range was longer than `D`) and the completion table is
   full, a block whose `max_score` is below the table's lowest score is
   skipped. Before skipping, the block's first sequence is compared with `D`:
   if it no longer starts with `D` the lookup ends, so skipping never runs
   past the range.
5. Merge the exact matches (score plus `T9_EXACT_BONUS`) and the completions
   by rank into the result; the whole list fits `T9_MAX_CANDIDATES`.

Decoders expose counters (entries decoded, blocks skipped) for host measurements.
Entries decoded counts entry headers walked by the scan; the binary search
probes (at most `ceil(log2(block_count))` block-first headers) and the range
check before a skip are not counted.

### Generated header layout

```c
#define T9_DICT_WORD_COUNT 12345
#define T9_DICT_BLOCK_SIZE 64
#define T9_DICT_BLOCK_COUNT 193
#define T9_DICT_DATA_BYTES 56789
static const uint8_t  t9_dict_bits[] = { ... };
static const uint32_t t9_dict_block_offsets[T9_DICT_BLOCK_COUNT + 1] = { ... };
static const uint8_t  t9_dict_block_max_score[T9_DICT_BLOCK_COUNT] = { ... };
```

The header also records its inputs as comments: generator version, input file
sha256, word count before and after each filter, and the `--max-bytes` budget.

### Generator input rules

`word<TAB>zipf` lines (a run of spaces also separates), `#` comments and blank
lines ignored; a line without a numeric zipf is an error. Words must be
lowercase `a-z`, 1..24 letters; other words are rejected and counted by reason.
A repeated word keeps its first occurrence. Scores use `floor(zipf * 8 + 0.5)`
clamped to 0..63, matching the awk fixture rule. `--max-exact` (default 10,
`T9_MAX_EXACT`) keeps the best-ranked words of every digit sequence and drops
the rest before the byte budget is applied. An empty result is an error.
After encoding, a Python reference decoder walks the whole bitstream and the
build fails unless every entry, block offset and block max score matches.
